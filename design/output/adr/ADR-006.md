# ADR-006: パスワードハッシュアルゴリズム

## メタ情報

- ADR-ID: ADR-006
- タイトル: パスワードハッシュアルゴリズム（bcrypt）
- ステータス: Accepted
- 日付: 2026-07-15
- 関連REQ-ID: FR-001, FR-002, NFR-SEC-001
- 関連チケット/PR: —

## 1. Context

- 背景: 会員登録（FR-001）でパスワードをDBに保存する際、NFR-SEC-001の「パスワードはハッシュ化保存」を満たす必要がある。
- 課題: OQ-005として「パスワードハッシュアルゴリズムの指定（bcrypt等）は設計フェーズで確定が必要」とされていた。
- 制約: Node.js（TypeScript）環境。広く採用されライブラリの成熟度が高いアルゴリズムを選ぶ。

## 2. Decision

- 採用する決定事項: **bcrypt（`bcryptjs` ライブラリ、cost factor = 12）**を採用する
- 適用範囲: 会員登録（パスワード保存）・ログイン（パスワード照合）
- 実装方針:
  - `bcryptjs` パッケージを使用（ネイティブバインディング不要でビルドが簡潔）
  - ソルトコスト: **12**（セキュリティと応答速度のバランス。2024年時点のOWASP推奨は10以上）
  - パスワード登録: `bcrypt.hash(plainPassword, 12)` でハッシュ生成 → DBに保存
  - パスワード照合: `bcrypt.compare(plainPassword, storedHash)` → 結果に関わらず汎用エラーメッセージを返す（NFR-SEC-006）
  - プレーンテキストのパスワードはログ・レスポンスに一切含めない

## 3. Alternatives

- 代替案A: **argon2**
  - 不採用理由: Node.js環境でのネイティブモジュールのビルドが必要でCI/CDの複雑性が増す。bcryptの成熟度と普及率で今回は十分
- 代替案B: **SHA-256（ソルトなし）**
  - 不採用理由: レインボーテーブル攻撃に対して脆弱。パスワードハッシュに汎用ハッシュ関数を使用するのはOWASP違反
- 代替案C: **PBKDF2**
  - 不採用理由: bcryptと比較してNode.jsエコシステムでの利用実績・ライブラリ成熟度が劣る

## 4. Consequences

- 期待効果: bcryptのソルト組み込みにより同一パスワードでも異なるハッシュが生成され、レインボーテーブル攻撃を防止。cost factor 12でハッシュ計算に約200-400msかかりブルートフォース攻撃コストを増大
- トレードオフ: ログイン処理にハッシュ計算のオーバーヘッドが発生するが、NFR-PERF-002（5秒以内）の範囲内で許容可能
- リスク: cost factorはサーバーのCPUスペックに依存するため、Azure環境での実測値で調整が必要な場合がある

## 5. Traceability

- NFR-SEC-001 → bcrypt によるハッシュ化保存
- NFR-SEC-006 → ハッシュ照合結果に関わらず汎用エラーメッセージを返すことでアカウント存在推測を防止
- FR-001 → 会員登録時のパスワードハッシュ生成
- FR-002 → ログイン時のパスワード照合

## 6. Open Questions

- OQ-005（解決）: bcrypt（cost factor = 12）を採用する
