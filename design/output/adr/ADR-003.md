# ADR-003: 在庫・残席の排他制御方式

## メタ情報

- ADR-ID: ADR-003
- タイトル: 在庫・残席の排他制御方式（SELECT FOR UPDATE によるDBレベル悲観的ロック）
- ステータス: Accepted
- 日付: 2026-07-15
- 関連REQ-ID: FR-006, FR-008, FR-009, ERR-003, ERR-005, NFR-AVL-001〜004, C-DATA-003
- 関連チケット/PR: —

## 1. Context

- 背景: 商品注文確定（FR-008）とチケット購入確定（FR-009）では、在庫・残席の減算とレコード登録をアトミックに処理する必要がある（NFR-AVL-001〜004）。同時リクエスト時に在庫を超えた販売が発生するリスクが高い（RSK-001, RSK-002）。
- 課題: 在庫・残席の読み取りから更新までの間に他のトランザクションが割り込んだ場合のロストアップデートを防ぐ方式を決定する必要がある。
- 制約: DBはPostgreSQL。ORMはPrisma（`$transaction` APIが利用可能）。

## 2. Decision

- 採用する決定事項: **PostgreSQL の SELECT FOR UPDATE による悲観的ロック + Prismaトランザクションで排他制御**を採用する
- 適用範囲: 注文確定（FR-008）・チケット購入確定（FR-009）のサービス層
- 実装方針:
  ```
  await prisma.$transaction(async (tx) => {
    // 1. 在庫/残席を FOR UPDATE でロック取得
    const product = await tx.$queryRaw`
      SELECT stock FROM products WHERE id = ${productId} FOR UPDATE`;
    // 2. 在庫確認（不足なら例外throw → 自動ロールバック）
    if (product.stock < quantity) throw new InsufficientStockError();
    // 3. 在庫減算
    await tx.product.update({ where: { id }, data: { stock: { decrement: quantity } } });
    // 4. 注文/購入レコード登録（スナップショット含む）
    await tx.order.create({ data: { ... } });
  }); // コミット or ロールバック
  ```
  - 注文確定失敗時は Prismaトランザクションが自動ロールバックし、不完全注文を残さない（ERR-005, NFR-AVL-003〜004）
  - カート追加時（FR-006）は在庫減算しない（業務ルール）。在庫チェックのみ行う

## 3. Alternatives

- 代替案A: **楽観的ロック（バージョン番号による更新競合検出）**
  - 不採用理由: 競合発生時にクライアント側でリトライが必要になり、UI実装と整合性管理が複雑化する。映画チケットの残席は競合頻度が高いケースが想定されるため悲観的ロックを優先
- 代替案B: **アプリケーション層のミューテックス（Node.jsシングルスレッド依存）**
  - 不採用理由: 水平スケール時に機能しない。Azureへのデプロイ時に複数インスタンス起動の可能性がある
- 代替案C: **在庫予約テーブルによる2フェーズコミット**
  - 不採用理由: 実装複雑性が高く、今回のスコープでは過剰

## 4. Consequences

- 期待効果: DBレベルで排他ロックを取得するため、同時リクエスト時の在庫/残席超過販売を防止できる（NFR-AVL-001〜004達成）
- トレードオフ: ロック待ち時間が発生し高負荷時にレスポンス遅延の可能性がある。しかし映画チケット・物販ECのトラフィック規模では許容範囲内と判断
- リスク: デッドロック（複数商品を同一注文で購入する場合）。対策として常に `productId` の昇順でロックを取得する

## 5. Traceability

- NFR-AVL-001 → 注文登録と在庫減算を同一トランザクションで実行
- NFR-AVL-002 → チケット購入登録と残席減算を同一トランザクションで実行
- NFR-AVL-003 → 注文確定失敗時の自動ロールバック
- NFR-AVL-004 → チケット購入失敗時の自動ロールバック
- ERR-003 → 在庫不足例外を補足し、フロントに在庫不足メッセージを返す
- ERR-005 → Prismaトランザクションのロールバックで不整合データを残さない

## 6. Open Questions

- OQ-002（解決）: 上映回の販売終了判定を `sales_end_at < NOW()` または `starts_at < NOW()` で行うかは `starts_at` 基準（上映開始時刻を過ぎた回は購入不可）とする。`sales_end_at` が設定されている場合はその時刻を優先する
