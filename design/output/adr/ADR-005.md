# ADR-005: カート永続化方式

## メタ情報

- ADR-ID: ADR-005
- タイトル: カート永続化方式（DBテーブルへの永続化）
- ステータス: Accepted
- 日付: 2026-07-15
- 関連REQ-ID: FR-006, FR-007, FR-008, DM-004
- 関連チケット/PR: —

## 1. Context

- 背景: カート（FR-006〜007）は会員ユーザーが複数商品をまとめて購入準備するための機能。会員単位のカートデータを保持する必要がある（DM-004）。
- 課題: OQ-001として「カートの有効期限（セッション終了後のカートは保持するか？）」が未定義だった。DB永続化するかセッション管理するかを決定する必要がある。
- 制約: カート追加時は在庫減算しない（FR-006業務ルール）。

## 2. Decision

- 採用する決定事項: **Cart / CartItem テーブルへのDB永続化**方式を採用する。有効期限は30日とする
- 適用範囲: カート追加・変更・注文確定（FR-006〜008）
- 実装方針:
  - `carts` テーブル: `id`, `user_id`, `updated_at`
  - `cart_items` テーブル: `id`, `cart_id`, `product_id`, `quantity`, `added_at`
  - 会員1人につき1カートを保持（カートが存在しない場合は自動生成）
  - 同一商品追加時は数量を加算（UPSERT）
  - 注文確定後はカートをクリア（cart_itemsを全削除）
  - 有効期限: `updated_at` から30日を超えたカートはバッチで削除（OQ-001解決）
  - カートへのアクセスは `user_id` で必ず絞り込み、他会員のカートへのアクセスを防止（C-AUTH-004）

## 3. Alternatives

- 代替案A: **サーバーサイドセッション（Redisなど）でカートを管理**
  - 不採用理由: ADR-002でRedisを採用しないことを決定済み。セッション終了でカートが消えるとユーザー体験が悪い
- 代替案B: **ブラウザのlocalStorageに保存**
  - 不採用理由: 会員の複数端末間での同期ができない。ログアウト後のデータ残留リスクがある
- 代替案C: **有効期限なしでDB永続化**
  - 不採用理由: 長期放置データによるDB肥大化（RSK-004）のリスクがある

## 4. Consequences

- 期待効果: ブラウザを閉じても・再ログインしてもカート内容が保持される（ユーザー体験向上）。30日の有効期限でDB肥大化を防止
- トレードオフ: DB永続化によりAPIのI/Oが発生するが、カート操作はNFR-PERF-002（5秒以内）の範囲内で対応可能
- リスク: カート内商品が在庫切れ・販売終了になった場合、注文確定時に再チェックが必要（FR-008のバリデーションで対応済み）

## 5. Traceability

- DM-004 → Cart/CartItemテーブル設計に準拠
- FR-006 → カート追加（UPSERT）でDB永続化
- FR-007 → カート変更（UPDATE/DELETE）でDB更新
- FR-008 → 注文確定後にcart_itemsをクリア
- C-AUTH-004 → user_idでカートアクセスを制限

## 6. Open Questions

- OQ-001（解決）: カートの有効期限を30日（`updated_at` 基準）と決定した
